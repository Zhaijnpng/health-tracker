# 血检日记

适用于 GitHub Pages 的个人静态 HTML 应用。首页采用 Excel 风格对照表：指标为行，检查日期为列。图片用 Tesseract.js 在浏览器中 OCR，PDF 优先读取文字，扫描页转图片识别。识别结果须对照报告校对。

## 使用

运行 `node server.cjs`，访问 http://127.0.0.1:4173/ 。上传一份报告，确认日期、各项名称、数值和单位后保存。原文件在上传时存入 IndexedDB，识别失败时仍保留，可在报告档案中重新识别或下载。数值在确认后存入 localStorage。相同日期的多次结果在同一格逐行保留，缺项显示横线，不同单位分行、不自动换算。

点击指标名称或该行，即可在表格下方查看详细变化图、首末差值、逐次结果以及附来源的指标说明。也可在详情中切换指标。横轴使用真实日期间隔，缺测断线；双边参考范围以淡绿区域显示，点可鼠标悬停、点击或键盘选择。界限结果仅显示阈值标记，不连接曲线、不参与首末变化计算；同日多个结果不作平均。说明属于一般知识，未知指标提供待核对提示，不自动推测含义。

“导出数值备份”仅包含数值；“备份报告与数值”包含所有原始文件和数值，可通过“恢复完整备份”合并恢复。完整备份包含敏感健康信息，请自行妥善保存。个人界面不含账号登录或访问控制。

## 发布到 GitHub Pages

1. 在 GitHub 创建仓库，将 index.html、style.css、personal.css、app.js、archive.js、matrix.mjs、trends.mjs、metric-info.mjs、metric-detail.mjs、README.md 上传到仓库根目录。
2. 仓库 Settings → Pages → Build and deployment，选择 Deploy from a branch。
3. 选择 main 分支与 /(root)，保存。部署后使用该页面给出的访问地址。

只有应用源码需要上传；不要提交个人报告、导出备份或真实健康记录。GitHub Pages 地址通常可以公开访问，但每位使用者的数据分别保存在自己的浏览器里。

## 数据与限制

- 点击指标旁的 ☆ 可星标置顶，★ 可取消。星标保存在当前浏览器，并包含在数值备份和完整备份中。表格与 CSV 均按“星标 → 曾有异常 → 其他”排列。
- 异常仅依据每次报告填写的参考范围或报告异常标记判断，超范围数值红色显示并标注方向。支持闭区间 `3.5-9.5` 和 `<1`、`<=1`、`>1`、`>=1`。缺少或无法解析的范围不判为正常，亦不自动套用通用参考值。原报告有异常标记时，以该标记优先。
- 最新检查日期有异常则标“最新异常”，只有较早记录异常则标“历史异常”；该项目最新日期缺失时，较早异常也保留在前排。
- 最近两个检查日期中，同一指标都有记录且全部在范围内时，取消其历史异常提示、自动置顶及绿色显示，历史异常数值仍保留红色。缺测或未判定会中断连续正常；手动星标不受影响。只有最新一次正常时，继续显示绿色“历史异常 · 最新正常”。
- 最近两个检查日期都缺测的项目不再因历史异常自动置顶，但保留历史异常标记、原始数值和手动星标。只缺测一次时保持原排序规则；未判定的已有数值不算缺测。
- 录入结果可选择“小于/大于”等关系，界限结果会保留符号，不作为精确值比较参考范围。病毒核酸报告的检测下限不是正常参考范围。整理资料时按采血日期归列，原件档案可保留另一个报告日期；手工分类与仪器分类名称不同的项目保持独立。

- localStorage 保存数值，IndexedDB 保存报告原件；不提供账户或跨设备自动同步。刷新、关闭后仍保留，但清理浏览器、切换浏览器、设备或域名无法读取原存储。请定期下载完整备份，浏览器存储不等于永久云端保存。
- 外部 CDN 加载 PDF.js、Tesseract.js、识别模型和字体，需要网络。报告处理在本地浏览器进行，第三方代码仍在页面权限内运行。
- OCR 对复杂表格、模糊图片和特殊符号可能错漏；提取采用启发式行解析。请检查参考范围是否被误识别为结果、指标名称及单位是否一致。
- 目前不自动判断异常、不提供医学解释。日期需要用户确认，不能把不同日期报告一次性保存到同一日期。
- 浏览器需要支持 ES modules、WebAssembly、Web Workers、crypto.randomUUID。

技术参考：[PDF.js](https://mozilla.github.io/pdf.js/)、[Tesseract.js](https://github.com/naptha/tesseract.js)。

## 云端版本

云端由 Supabase Auth、Realtime 及开启 RLS 的私有数据表提供。只有已授权邮箱能读取，管理员能修改和添加/撤销只读邮箱。原件目前存储在有 25MB 文件上限的私有附件表。网页源码和发布产物不包含任何报告或健康记录。网页公开，数据不公开。

在 GitHub 仓库 Settings → Pages 中选择 GitHub Actions，推送 main 分支后自动测试并发布。管理员通过邮箱登录；新项目默认邮件服务可能只允许组织成员收信，向组织外用户开放登录前需在 Supabase 配置自有 SMTP。请在 Supabase Auth URL Configuration 中添加实际网站 URL。

只有登录完成且获授权后才读取云端，只有管理员可写入。并发修改使用 revision 条件更新；冲突时不覆盖云端，保留本机会话草稿供下载。页面重新聚焦及每 30 秒复核云端，数据变更通过 Realtime 通知更新。撤销权限不会删除对方此前下载的副本。

本机版本原有数据仍保留。登录后以云端为准，管理员可手动合并本机报告；正式网站不能自动读取另一个 localhost 网址的浏览器存储。
